- Mood administration uses `moods.functions.ts` with server-verified staff access and audit logging; a database trigger synchronizes renamed/deleted names in brand/reel arrays atomically.
- Likes/favorites/shared favorites pages: `favorites.functions.ts` (like counts via service-only SQL `directory_like_counts`; public page only when `favorite_pages.is_public`, filtered by `brand_visible`).
- Directory page settings live in `site_settings` key `directory` (merged over defaults by `mergeSettings` in settings.ts); hand-picked featured reels in `directory_featured_reels`; featured selection is the pure `resolveFeatured()` so the admin preview and the site agree.
- Directory opens are recorded from intentional page open handlers, never modal renders or admin previews; append-only events use server-derived workspace/time and idempotent event ids, with service-only validated SQL helpers exposing visible-reel weekly aggregates to the shared featured selector.

- Directory: `directory.functions.ts` lists; `moods.functions.ts` manages moods with sync triggers; categories are shared. Mood pages, filters and counts match each reel's own mood tags plus its brand's moods (lowercased) in `directory_faceted_search`, so tagged reels appear under every mood they carry.
- Brand mood arrays and approval/link creation carry no count cap (`BRAND_MOODS_MAX` is a safety ceiling only); approval still requires valid master moods and staff verification, so application and approval rules agree.
- Reel moods are owner-editable at any time through `saveReelMoods` (Account → Published reels), so a wrong AI tag never needs a re-share. Names the master list lacks go to `mood_requests` (requester-scoped RLS, one pending row per name, decided by staff under Admin → Moods); only approved names reach `moods`, so `cleanMoods` keeps every stored mood valid.
- Reel brand touch points share `BrandLink` (a plain text link to `/directory/$slug`); cards have no brand logo tile — the linked name carries the destination so the grid and featured captions keep one treatment without extra data reads.
- Directory headline greeting: config in `site_settings` key `directory_greeting` (seeds in `greeting.ts`), one pure `chooseGreeting()` shared by site and admin preview; geo/weather via `getVisitorContext` (never stored); analytics in `directory_greeting_log`.
- aimante.co is served by the same Directory routes via the router `rewrite` in `src/lib/site/brand-site.ts`; cross-domain 301s live in `src/server.ts` (`domainRedirect`, real domains only); previews use `?brand=aimante` (cookie); root context `site` picks the shell, head tags, robots and sitemap.
- Category hints are read from `categories` through `categories.functions.ts`, with staff-only edits and audit records; public filters share its catalog query so edits reach visitors without duplicating copy.
- Greeting events go through a validated public server function; direct browser inserts are revoked so clients cannot supply record ids or timestamps.
- Aimanté applications extend `brand_requests`; staff approval creates one draft editorial brand before publication.
- Shared reel videos are copied to `<ws>/directory/<ad_id>.mp4` (`pinReelVideo`) so the 30-day exports/ cleanup never removes them; never store an exports/ path in `directory_reels.video_url`.
- Showcase featuring: staff-only `setReelFeatured`; `listSiteReels` merges featured live Directory reels (`source: "client"`, pure helpers in `src/lib/site/featured-reels.ts`); Aimanté/favorites callers filter them out, and client reels show no site-reel heart so saved favorites keep their ids.
- Live reel replacements: owners submit via `submitReelUpdate` into `pending_*` columns (`<ws>/directory/<ad>-pending.mp4`); only staff `decideReelUpdate` swaps `video_url`, enforced by trigger `guard_reel_video_update`, so the live version never changes without review.
- Directory grid order: `directory_faceted_search` treats Showcase-featured Directory reels as featured and sorts them by `showcase_order` alongside site reels' `sort_order`, so the admin Website Reels order is the single curated order everywhere. The route passes a per-visit `seed` that shuffles the remaining reels (md5 of id+seed) while keeping pagination stable within the visit; an empty seed falls back to newest-first.
- Directory search maps all five website format codes to editor ratios; FeaturedBand sizes each ratio explicitly so portrait and landscape reels keep their real proportions.
- Directory text search matches every word against title, brand name, category, moods, reel tags, reel description and brand description (`extra_text` in `directory_faceted_search`); keep new searchable metadata inside that field so search stays complete.
- Directory listings server-render page 1 from the route loader (seeded into the infinite query) so cards, alts and JSON-LD are in the first HTML; /c/ and /mood/ intros come from editable `categories.page_intro` / `moods.page_intro`, and the shared `MIN_LISTING_BRANDS` rule in `listing.ts` drives both page noindex and sitemap inclusion so they never disagree.
- Guides: `guides` table (public reads published only, staff writes via `guides.functions.ts`); aimante.co `/guides` maps to internal `/aimante/guides`; brand thumbnails resolve server-side in `guides.server.ts`; seasonal pure rules in `guides.ts` keep guides indexable all year and match homepage countdown events by season id.
- Badge: `/badge/{light|dark}.svg` is generated by `badge.ts` (also builds the copyable snippets); aimante.co `/brand-kit` maps to the signed-in `/app/account/brand-kit`. The badge is optional and never a listing condition.
- Stage view (/stage, /stage/$mood) loads via `getStage` with the Directory's per-visit seed passed from the reel popup, so it plays the same list in the same order as the grid; the popup's only entry point is `ReelNav.stage`.
